## Kanboard Neo

### Rôle retenu

Kanboard Neo reste l'interface humaine candidate. Les dépôts et sources locales restent les sources de vérité. La première phase est un aperçu hors ligne d'une projection assainie, sans insertion dans la base Kanboard.

### Régressions du dashboard — issue #9 / PR #10

L'audit du dernier dashboard a détecté :

- un appel inexistant à `countByAssignee()` ;
- un appel inexistant à `getProjectsActivities()` ;
- une liste d'identifiants construite avec `findAll()` au lieu de `findAllByColumn()` ;
- un filtre multiple transmis à `eq()` au lieu de `in()`.

La PR #10 corrige ces points et ajoute deux tests contrôleur. Ses linters et son build Docker réussissent. Les suites fonctionnelles restent dépendantes du socle de tests #14.

### Configuration publique portable — issue #11 / PR #12

Le dépôt public suivait des fichiers contenant des chemins et paramètres propres à une machine. La PR #12 :

- retire les configurations machine du suivi ;
- les ajoute à `.gitignore` ;
- fournit des exemples portables ;
- ajoute `AGENTS.md`, `STATUS.md`, `DECISIONS.md` et le contrat d'intégration du portefeuille ;
- n'active aucune connexion ou écriture.

Observation de sécurité : le compte spécial JSON-RPC associé au jeton global ne constitue pas une identité à privilèges minimaux. Une future intégration devra utiliser un compte dédié, des projets limités et une allowlist de procédures.

### Socle de tests — issue #13 / PR #14

Les personnalisations Kanboard Neo avaient été intégrées sans migration complète des tests amont :

- workflow par défaut à six colonnes ;
- nouveaux offsets d'identifiants entre projets ;
- badges de priorité nommés et iconés ;
- thème Linear par défaut.

La PR #14 reste limitée aux tests. La progression observée est passée d'un premier arrêt après 15 tests à plus de 640 tests. Les intégrations SQLite, PostgreSQL et MySQL, les linters et le build Docker ont déjà réussi sur des commits intermédiaires.

Les tests de mécanismes génériques conservent explicitement leur ancien fixture à quatre colonnes. Les tests portant réellement sur le board par défaut sont migrés vers :

```text
Triage → Backlog → Started → In Review → Done → Canceled
```
