# Skill Project Optimizer — Plan d'implémentation

## Problème identifié

```
229 skills total
├── 174 archived (472K tokens waste si chargés)
├── 31 actifs
│   ├── 18 sans tags (58%) → impossible à filtrer
│   ├── 13 sans triggers → chargement aveugle
│   └── Plusieurs > 5K tokens chacun
└── Total actifs: ~76K tokens (306K chars)
```

**Patterns de perte de token :**
1. Skills archivés encore scannés au démarrage
2. Skills sans tags = pas de filtrage contextuel
3. Skills sans triggers = chargés même si non pertinents
4. Skills monolithiques (entier du SKILL.md chargé)
5. Pas de profiling par projet (même config partout)

## Solution : skill-project-optimizer

### Concept

Un outil qui :
1. **Scanne** tous les skills disponibles et extrait metadata (tags, taille, triggers)
2. **Profile** un projet donné (quels skills sont pertinents)
3. **Génère** un `.skills-profile` qui liste les skills à charger
4. **Estime** les économies de tokens
5. **Filtre** les skills par tags, taille, pertinence

### Fichiers à créer

```
skills/skill-project-optimizer/
├── __init__.py
├── scanner.py          # Scan skills + extraction metadata
├── profiler.py         # Profile un projet (analyse codebase)
├── optimizer.py        # Génère .skills-profile + estimations
├── cli.py              # CLI (typer + rich)
├── templates/
│   └── skills-profile.yaml  # Template du profil généré
└── README.md
```

### Format du .skills-profile.yaml

```yaml
# .skills-profile — Generated by skill-project-optimizer
# Place this file in your project root
# Hermes will only load skills listed here

project:
  name: "mon-projets"
  type: "web-app"  # web-app, cli, ml, data, infra, etc.
  languages: ["python", "typescript"]
  frameworks: ["fastapi", "react"]

skills:
  # Core — always loaded
  always:
    - writing-plans
    - code-rules
    - simplify-code

  # Conditional — loaded based on context
  conditional:
    - name: github-workflow
      when: "git remote contains github.com"
    - name: turboquant
      when: "path contains trading/ or finance/"
    - name: hailo-vision
      when: "path contains vision/ or camera/"

  # Disabled — explicitly excluded
  disabled:
    - ascii-video        # Not relevant
    - touchdesigner-mcp  # Not installed
    - comfyui            # Archived

# Token savings
stats:
  total_available: 76570  # tokens
  total_loaded: 15000    # tokens
  savings_percent: 80%
```

### Workflow

```bash
# 1. Scanner tous les skills disponibles
skill-optimizer scan

# 2. Profiler un projet
skill-optimizer profile ~/projects/mon-projet

# 3. Générer le .skills-profile
skill-optimizer optimize ~/projects/mon-projet --output .skills-profile

# 4. Voir les stats
skill-optimizer stats ~/projects/mon-projet

# 5. Comparer avec/sans optimisation
skill-optimizer compare ~/projects/mon-projet
```

### Intégration Hermes

Le `.skills-profile` est lu au démarrage d'une session :
- Si présent → seuls les skills listés sont chargés
- Si absent → comportement par défaut (tous les skills)
- Les skills "always" sont toujours chargés
- Les skills "conditional" sont chargés si la condition match
- Les skills "disabled" ne sont jamais chargés
