## Synthèse des sources

### Vidéo 1 — Julian Goldie: "Fable 5: FREE Tools Cut Tokens by 95%!"
10 tactiques de réduction tokens pour Fable 5:
1. Model routing (architect vs builder — Fable plan, Opus build)
2. Plan with expensive, implement with cheap (59% savings)
3. Adjust effort levels per task
4. **Headroom** — 60-95% compression (proxy/library/MCP, reversible)
5. **Ponytail** — "lazy senior dev" skill, 54-94% code reduction
6. Trim rules/Claude MD (lighter context)
7. Turn off web search by default
8. Manual /compact at 60% (don't wait for auto)
9. Post-compact brief (5-line handoff)
10. Two-hour /clear with handoff note

### Vidéo 2 — Mehul Mohan: "2X Cheaper Fable 5?!"
**PX Pipe** — Text-as-image billing exploit:
- Image tokens billed by dimensions (fixed cost)
- Dense text in small image → 2x cheaper
- Proxy intercepts /v1/messages, converts text to PNGs
- Fable 5 reads renders at 100/100 accuracy
- 59-70% end-to-end bill reduction
- 48K chars system prompt → 25K text tokens vs 2.7K image tokens
- Caveat: exact strings NOT byte-safe in images

### Vidéo 3 — Ben AI: "This Skill Instantly 10x'es Every Claude Output"
**Re-fresh skill** — contexte optimisé pour 10x la sortie Claude.
Principe: refresh du contexte plutôt que simple compact.

### Vidéo 4 — IA Talkshow: "Claude Fable: The ULTIMATE guide"
**Loop Engineering / Mythos 5** — framework agentique:
- #loopengineering: plan → build → review en cycles
- #mythos5: modèle classe Mythos (accès restreint)
- Agent building patterns pour modèles nouvelle génération

### Vidéo 5 — Discover AI: "Open 32B w/ AutoMemory beats Opus: HOW? (Stanford)"
**AutoMem (Stanford)** — mémoire comme compétence entraînable:
- Memory management = trainable skill, not fixed module
- Model decides WHAT to encode, WHEN to retrieve, HOW to organize
- File-system operations = first-class actions
- Two loops: strong LLM reviews trajectories → rewrites memory structure
- Agent's own good memory decisions become training signal
- 32B open model competitive with Claude Opus 4.5
- 2x-4x improvement on Crafter, MiniHack, NetHack

### Repo 1 — Headroom (headroomlabs-ai/headroom)
Rust, 1848 commits, Apache 2.0. "Compress tool outputs, logs, files, and RAG chunks before they reach the LLM."
- **Multi-mode:** proxy, library, middleware, MCP server
- **CCR:** reversible compression (unlike RTK which is lossy)
- **Memory module:** persistent learning across sessions
- **Failure learning:** learns from compression mistakes
- **Cache optimization:** preserves prompt caching
- **Dashboard:** live savings tracking
- Ships RTK binary for shell output rewriting
- Covers ALL content types, not just CLI

### Repo 2 — PX Pipe (teamchong/pxpipe)
TypeScript, 298 commits, MIT. "Cut Fable 5 token usage by rendering text context as images."
- **Billing exploit:** image tokens = fixed cost by dimensions
- **Proxy:** intercepts /v1/messages, converts bulky text → PNGs
- **Gateway logic:** per-request profitability estimator
- **Dashboard:** live savings, kill switch, side-by-side comparison
- **Benchmarks:** 100% arithmetic accuracy on Fable 5, 93% on Opus
- **Honest:** documents failure modes (exact strings not byte-safe)
- **Events log:** ~/.pxpipe/events.jsonl for reproducible measurement

## Plan d'amélioration — Phase 1 (🔴 Priorité haute)

### §1 — Compression universelle (Headroom-inspired)
**Gap:** botte compresse le CLI mais pas les logs, fichiers, RAG, tool outputs.
**Solution:** étendre le `botte` wrapper en proxy/middleware multi-type.

| # | Tâche | Fichiers | Effort |
|---|---|---|---|
| 1.1 | Créer `skills/universal_compressor/` — pipeline de compression multi-type (text, JSON, logs, tool output) | `compressor.py` | 2h |
| 1.2 | Ajouter mode MCP server (compatible Claude Code, Cursor, Hermes) | `mcp_server.py` | 1h |
| 1.3 | Implémenter compression réversible (CCR-like) — pouvoir restaurer l'original | `reversible.py` | 1h30 |
| 1.4 | Intégrer avec `context_profiler` pour mesurer le gain réel | `profiler_hook.py` | 30min |
| 1.5 | Dashboard de savings (inspiré Headroom) | `dashboard.py` | 1h |

### §2 — Ponytail "Decision Ladder" (Ponytail-inspired)
**Gap:** Pas de vérification "est-ce vraiment nécessaire?" avant d'écrire du code.
**Solution:** skill qui force une échelle de décision avant chaque implémentation.

| # | Tâche | Fichiers | Effort |
|---|---|---|---|
| 2.1 | Créer `skills/decision_ladder/` — échelle YAGNI stricte | `ladder.py`, `SKILL.md` | 1h |
| 2.2 | Échelle: stdlib? → regex? → 1-liner? → module existant? → nouveau code? | `checks.py` | 45min |
| 2.3 | Intégrer avec `workflow-check` comme hook pré-code obligatoire | `hook.py` | 30min |
| 2.4 | Métrique: % de lignes évitées (comme Ponytail: 54% avg) | `metrics.py` | 30min |

### §3 — AutoMemory / Metamemory (Stanford-inspired)
**Gap:** control_loop est basique (record→analyze→adapt). Pas de mémoire entraînable.
**Solution:** mémoire comme compétence apprenante avec file-ops first-class.

| # | Tâche | Fichiers | Effort |
|---|---|---|---|
| 3.1 | Étendre `control_loop` avec `memory_ops` — file-system comme action first-class | `memory_ops.py` | 2h |
| 3.2 | Two-loop architecture: LLM fort review → réécriture structure mémoire | `metamemory.py` | 2h |
| 3.3 | Training signal: bonnes décisions mémoire → données d'entraînement pour µNN | `memory_trainer.py` | 1h30 |
| 3.4 | Intégrer avec `trajectory` skill existant | `trajectory_hook.py` | 1h |

## Notes

- **Pas de PX Pipe par défaut** — le billing exploit est Anthropic-spécifique et pourrait être patché. Proposé comme option avancée avec avertissement.
- **Headroom est en Rust** — botte restera en Python stdlib+numpy. On s'inspire de l'architecture, pas du langage.
- **AutoMem est un paper Stanford** — l'implémentation sera simplifiée pour botte (pas de fine-tuning de LLM, on utilise les µNN existants).
- **Ponytail a 44K+ stars** — le concept est validé par la communauté. Le "decision ladder" est le pattern le plus rapidement actionnable.
