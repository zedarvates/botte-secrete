BOTTE SECRÈTE · CORRECTIF RÉEL ET REPRODUCTIBLE

Un test ignoré
n'est pas un test réussi.

Un vrai lancement de unittest découvre un test, l'ignore et termine sans erreur. L'ancien vérificateur de Botte validait son reçu malgré l'absence de test exécuté.

Avant : une validation injustifiée

Ancienne version extraite du commit public 4cffa4b. Le reçu déclare explicitement un test ignoré.

Botte : vérifié = vrai.
Le test de non-régression échoue.

Résultat de Botte · Échec du contrôle

Après : le reçu est refusé

Le correctif contrôle le nombre de tests ignorés. Si tous ont été ignorés, le reçu ne permet pas une validation.

Botte : vérifié = faux.
Le même test de non-régression réussit.

Résultat corrigé · Réussite du contrôle

Les pièces de l'exécution

Test réellement ignoré · Même reçu pour les deux versions · Code avant · Code après · Provenance · Empreintes

Ce défaut a été découvert dans le nouveau vérificateur de notre proposition GitHub. Ce n'est pas un incident de production ni une correction réalisée par un agent autonome. Le contrôle dépend toujours d'un exécuteur de confiance : les anciens reçus qui omettent le nombre de tests ignorés restent une limite de compatibilité.

Pour rejouer depuis un clone contenant le commit de référence :

python docs/demos/completion-proof/real_fix.py
