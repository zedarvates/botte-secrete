# Botte Secrète 2.0.0rc1 — External Pilot

Status: **pre-release candidate for bounded external pilots**.

This candidate exists so external collaborators can test a frozen version rather
than a moving development PR. It is not a declaration that Factory Assurance is
complete, generally production-ready, or safe for unbounded autonomy.

## Source lineage

- Release branch: `release/2.0.0-rc1-external-pilot`
- Factory Assurance source snapshot: `287dc5d97d49e8da301ec2c0a73ba8d84e048d67`
- Source Git tree: `7f65152c12cf8c1449178bfca769f65386fe0927`
- Source PR: Botte Secrète #119 (draft; not merged at preparation time)
- Previous public release: `1.9.0`

The release-preparation commit changes packaging/version/release documentation
only. It must receive its own CI evidence before being offered to external
pilots. Do not transfer green status from the source snapshot to the release
commit automatically.

## Intended pilot mode

External users should start with `observe`, `consultative`, or `shadow` mode.
The candidate must not be presented as granting merge, deployment, publication,
model activation, destructive-operation, or security-certification authority.

The pilot protocol is in `docs/external-pilot-protocol.md`.

## What this candidate adds over 1.9.0

- deterministic Factory Assurance decision layer;
- mission / non-goal / forbidden-transformation boundaries;
- builder versus independent-judge separation;
- named agent governance for Conductor, Mousquetaires, Cardinal Red Team,
  Gauntlet, Monte Cristo and external/local workers;
- required evidence gates;
- positive + negative/mutation controls;
- private/external holdout boundary and public-safe holdout attestations;
- exact commit identity with exact Git-tree fallback for synthetic PR checkouts;
- adapters for capability-effect and observation contract shapes;
- consequence handoff (`hold` / `review_ready`) with no automatic merge/deploy;
- reusable deterministic assurance mutations;
- conservative control-loop evidence bridge with no policy application;
- real StoryCore shadow dark-lap fixture expected to remain `hold` while private
  holdout evidence is absent;
- external-pilot disclosure and reproducibility protocol.

## Known limits

- PR #119 is still a draft at preparation time.
- StoryCore's controlled negative mutation proof is being established separately.
- The real private/external holdout is not yet proven for the StoryCore dark lap.
- No authenticated holdout signer/issuer infrastructure is claimed.
- No Eurekai controller service, fleet registration or automatic promotion is
  included in this candidate.
- No external collaborator feedback has yet been incorporated.
- A green Botte CI run proves only the checks that actually ran; it is not a
  general security or correctness certification.

## Installation for a pilot

For reproducibility, prefer an exact commit instead of a moving branch. Once the
release-preparation CI is green, use the exact release-candidate SHA recorded in
this document/PR, for example:

```bash
python -m pip install "git+https://github.com/zedarvates/botte-secrete.git@<RC_SHA>"
```

Or clone and detach at the same SHA:

```bash
git clone https://github.com/zedarvates/botte-secrete.git
cd botte-secrete
git checkout --detach <RC_SHA>
python -m pip install -e .
```

Do not use `main`, `feat/factory-assurance-layer`, or the release branch name as
the reproducibility identity for published pilot results. Record the exact SHA.
